# **The Omnix: Dota 2 AI Game Guide**

# **Project Vision**

To lower the high barrier to entry for the game Dota 2 by providing a real-time, jargon-free AI companion that explains game mechanics, lore, and strategy through voice interaction. This tool acts as a "live coach" for new players, helping them navigate the complexities of the game without leaving the match environment.

# **Problem Statement**

Dota 2 is notoriously difficult for new players, primarily due to its vast, complex lore and intricate gameplay mechanics, which create a significant barrier to entry. This project aims to mitigate these challenges by acting as a real-time bridge for new users, helping them navigate the game's depth without feeling overwhelmed.

# **Core Technical Stack**

* **Speech-to-Text (STT):** OpenAI Whisper (Live transcription of user queries).  
* **Orchestration:** LLM (e.g., Gemini or GPT-4o) for query processing and natural language generation.  
* **Knowledge Engine:** RAG (Retrieval-Augmented Generation) utilizing a Vector Database.  
* **Data Ingestion:** Web Crawler (Scrapy or Firecrawl) targeting Dota 2 wikis, patch notes, and lore repositories.

# **Implementation Phases**

Following the structured development approach used in previous projects:

## **Stage 1: Foundation (MVP)**

* **Scope:** Text-based chatbot with a pre-populated RAG database.  
* **Knowledge Base:** Explicitly crawled data from the Dota 2 Wiki and official Hero pages.  
* **Jargon Filter:** Implementation of a system prompt that enforces "Beginner Mode," translating terms like "BKB" (temporary immunity), "CC" (crowd control), or "Stacking" into plain English descriptions.  
* **Query Support:** Lore questions, basic character attributes, and "Who is this?" identification.

## **Stage 2: Live Voice Integration (Goal)**

* **Scope:** Integration of Whisper AI for hands-free queries during gameplay.  
* **Real-time Transcription:** Processing microphone input to trigger RAG searches.  
* **Contextual Awareness:** The agent remembers the user's selected hero to prioritize relevant tips (e.g., "How do I play against the hero I'm facing?").  
* **Dynamic Crawling:** Periodic updates to the RAG database based on latest patch notes to ensure information accuracy.

## **Stage 3: Game-State Symbiosis (Not feasible in allotted time for the project)**

* **Scope:** Predictive assistance and deep game-state integration.  
* **Command Execution:** Similar to the concept in the IM Tool, the AI could suggest specific item builds based on the current enemy lineup.  
* **Active Listening:** The AI monitors game sounds or screen data (OCR) to proactively offer tips (e.g., "The enemy just used their ultimate, now is a good time to engage").  
* **Automated Reporting:** Post-game summary generated by the AI, explaining what went well and what lore secrets were encountered.

# **Knowledge Base Strategy (RAG)**

| Source Category | Content Type | Purpose |
| :---- | :---- | :---- |
| **Official Wiki** | Attributes, Spell mechanics, Counters | Factual accuracy for game questions. |
| **Lore Archives** | Character backstories, World-building | Engagement and immersion for new players. |
| **Beginner Guides** | "How-to" content, Pathing, Basics | Bridging the jargon gap with simple explanations. |
| **Patch Notes** | Balance changes, New items | Keeping the AI up-to-date with the "Meta." |
| **Community Hubs** | Dota 2 player hubs, comments, and tips | Player-driven tactics, community sentiment, and practical, non-official advice. |

# **Critical Constraints & Logic**

1. **Jargon Neutralization:** The LLM must be strictly instructed to avoid community slang unless it is explaining what a slang term means to a new player.  
2. **Low Latency:** Since Dota 2 is a fast-paced game, the Whisper \+ RAG pipeline must return answers within 2-3 seconds to remain useful.  
3. **Source Reliability:** The crawler must prioritize "Explicitly listed" high-quality sites (like Liquipedia or the official Dota 2 site) over general web indexes to avoid misinformation.
